# v0.8.10 — Lua-модули из установленной конфигурации

- Проверка стороннего `.conf` теперь сопоставляет `--lua-init=@путь` с установленными Lua-файлами по известным раскладкам nfqws2/nfqws/zapret; работающий процесс не обязан уже загружать этот модуль.
- Поддерживается `.lua` → `.lua.gz` fallback. Lua-файлы проверяются как обычные файлы внутри каталога установки; неизвестные пути, пропуски, traversal и символические ссылки отклоняются.
- Если в кандидатных профилях есть `--lua-desync`, а в `NFQWS_BASE_ARGS` не подключён `zapret-lib.lua`, проверочный конфиг получает доступные стандартные `zapret-lib.lua`, `zapret-antidpi.lua` и `zapret-auto.lua`, как в адаптации Zemidala.
- Inline `--lua-init` отклоняется: проверка принимает локальный установленный файл, а не исполняет Lua-код из чужого `.conf`.

## Проверки

- Rust: тесты адаптации Lua путей, gzip fallback, стандартных модулей и недоверенных путей; полный suite, форматирование и Clippy.
- Web: тесты, проверка типов и production-сборка.
- Физический роутер недоступен в этой среде; release CI выполняет ARM64-сборку.
