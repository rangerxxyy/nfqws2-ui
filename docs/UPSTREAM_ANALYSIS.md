# Анализ upstream-проектов

Исследование сделано по локальным shallow-клонам upstream на дату начала разработки. Клоны являются справочниками и не входят в новый git-репозиторий.

| Проект | Назначение | Вывод для nfqws2-ui |
|---|---|---|
| `zemidala/nfqws2-ui` | Полнофункциональная PHP/JS панель: служба, конфиги, списки, снимки, история, диагностика и обновления | Использовать как функциональный ориентир. Проверять фактический PID/cmdline, allowlist изменяемых файлов, делать backup перед изменениями. Не переносить старый стек. |
| `nfqws/nfqws-keenetic-web` | React/TS и PHP API, управление Entware init-службой | Проверенная модель вызова init-script и обработки результата команды; не считать `exec`-подход пригодным напрямую для новой Rust реализации. |
| `nfqws/nfqws2-keenetic` | Пакеты и init scripts для Entware/OpenWrt | Источник путей, формата PID-проверки и различий платформ. Entware: `/opt/etc/init.d/S51nfqws2`, OpenWrt: procd init; не подменять штатное управление прямым запуском бинарника. |
| `bol-van/zapret2` | Движок nfqws2, конфиги, Lua, документация | Панель не должна менять или встраивать движок. Конфигурация и управление только через штатную службу и ограниченные операции. |

## Изученные детали

- Актуальные на момент исследования shallow HEAD: zemidala `631878b` (VERSION 1.20.1), nfqws-keenetic-web `c225df3` (3.0.24), nfqws2-keenetic `5d155f3` (1.3.2), zapret2 `221d7df`; upstream-репозитории содержат MIT-лицензии (проверить license notices при заимствовании исходного кода).
- zemidala: `src/www/app.js`, `src/www/api.php`, `src/bin/nfqws-ui`, setup/install/package scripts. Изучены точки API сервиса, allowlist путей и логика снимков/записи с резервной копией.
- nfqws-keenetic-web: `web/public/index.php`; `nfqwsServiceStatus()` вызывает init-script `status`, `nfqwsServiceAction()` передаёт ограниченное действие init-script.
- nfqws2-keenetic: `etc/init.d/common`, Entware/OpenWrt init adapters. PID читается из файла, проверяется как положительное число, затем `/proc/<pid>/cmdline` сопоставляется с ожидаемым бинарником. На Entware служба дополнительно занимается firewall; нельзя управлять демоном напрямую вместо init-script.
- zapret2: движок и его конфиги остаются внешним системным компонентом.

## Соответствие возможностей

| Возможность | Справочник | Новая реализация |
|---|---|---|
| Состояние службы | nfqws2-keenetic init + zemidala | Вызов обнаруженного штатного init-script; нормализованные состояния running/stopped/error/unknown; проверка результата без ложного зелёного статуса. |
| Действия службы | nfqws-keenetic-web, zemidala | Только allowlist start/stop/restart (reload только если init-script поддерживает); без передачи произвольной команды. |
| Конфигурация | zemidala, zapret2 | Allowlist ожидаемых файлов; атомарная запись, snapshot до изменения, восстановление из валидированного snapshot. |
| Списки / профили | zemidala | После MVP; путь и операции ограничиваются allowlist, не раскрывать произвольную файловую систему. |
| Диагностика | zemidala, zapret2 | Отложено за MVP; не запускать тестовые процессы/iptables как побочный эффект установки. |
| Логи | zemidala | Ограниченное чтение известных логов с лимитом байтов/строк. |
| Пакеты/платформы | nfqws2-keenetic | Первое объявление поддержки только после сборки и испытания артефакта на целевой архитектуре. |
