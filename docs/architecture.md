# Архитектура v0.1

## Компоненты

- `web/`: React + TypeScript, собирается в статические файлы и не содержит mock-поведения в продакшене.
- `backend/`: компактный Rust HTTP API, обслуживает статические файлы и status/service/config/list/backup/log routes.
- `scripts/`: POSIX `sh` только для установки/удаления и системной интеграции.
- `docs/`: архитектура, протокол, установка и ограничения платформ.

## Границы безопасности

1. Bind на `0.0.0.0`; порт начинается с 1002 и выбирает следующий свободный до 1100. Ограничение доступа до LAN выполняется сетевой политикой/firewall роутера.
2. Вход, пароль, сессии и CSRF отсутствуют. Все API управления доступны без авторизации; доступ нужно ограничить LAN и firewall роутера.
3. Сервисные действия — enum, выполняются напрямую через `Command` с фиксированным init path и аргументом; shell не вызывается.
4. Конфигурационные пути выбираются из allowlist; не принимать клиентский абсолютный путь. Запись атомарная, backup/snapshot обязателен до записи.
5. Процессный статус не основывается только на наличии похожего имени в `ps`; использовать штатный статус службы и проверяемый PID/cmdline там, где доступно.
6. Запуск/обновление nfqws2 не должно запускать shell cron, менять firewall вручную или менять конфигурацию без явного действия администратора.

## Первый API-контракт

- `GET /api/health` — доступность backend.
- `GET /api/nfqws2/installation` — выбранный конфиг, известные кандидаты init/binary и literal list-path references с существованием и доступом; платформа называется Entware только при подтверждённом `/opt`-пути, остальные варианты помечаются unknown.
- `GET /api/status` — нормализованный status + причина + system metrics.
- `POST /api/service` — `{ action: start|stop|restart }`.
- `GET/PUT /api/config` — allowlisted config; PUT требует актуальный SHA-256 revision, создаёт backup, атомарно записывает, перечитывает и возвращает фактический путь и новую revision.
- `POST /api/nfqws2/config/preview` — `{content,key,value}` для быстрых настроек. Rust-парсер заменяет только диапазон значения существующего однозначного присваивания; сохраняет остальные байты, комментарии и переносы строк. Возвращает черновик без записи и перезапуска. Не исполняет shell; неподдерживаемый синтаксис возвращает 422, неизвестный ключ — 400, превышение размера — 413. Выбор MODE допускает только существующие непустые MODE_LIST/MODE_AUTO/MODE_ALL и намеренно оставляет их раскрытие для штатного init-скрипта после отдельного Apply. Это структурная проверка черновика, а не проверка совместимости стратегии установленным nfqws2.
- `GET /api/nfqws2/lists`, `GET/PUT /api/nfqws2/lists/:id` — существующие allowlisted файлы, найденные по literal ссылкам в активной конфигурации; неоднозначные и неразрешённые переменные пропускаются; PUT проверяет ревизию, создаёт backup, атомарно записывает и читает обратно.
- `GET /api/backups`, `POST /api/backups/:id/restore`.
- `GET /api/logs?source=...&tail=...` — только известный источник и ограниченный хвост.
- `POST /api/nfqws2/diagnostics/site` — `{host}`; выполняет ограниченные сетевые пробы и проверку обнаруженных списков, возвращает измеренные результаты по этапам. Публичные адреса проверяются до соединения, curl закрепляет разрешённый IP через `--resolve`, не следует редиректам и не наследует `.curlrc`/proxy. Один запрос одновременно, сетевой бюджет 45 секунд; дочерние процессы завершаются при отмене. HTTP-коды 400 для неверного имени, 409 для занятой диагностики, 504 при общем таймауте. Полное сопоставление профилей и изолированный обход nfqws2 ещё не реализованы.

## Платформы

Обнаружение путей должно быть явным. Entware использует `/opt/etc/init.d/S51nfqws2`. OpenWrt поддерживается только после отдельной проверки init script, package layout и прав. Нельзя сообщать поддержку платформы, если сборочный target и smoke-проверка не выполнены.
