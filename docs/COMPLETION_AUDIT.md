# Проверка исходного задания после v0.1.8

Дата: 2026-10-22. Проверенный код: `2ce5b88`, тег `v0.1.8`.
Релиз: https://github.com/rangerxxyy/nfqws2-ui/releases/tag/v0.1.8
CI: https://github.com/rangerxxyy/nfqws2-ui/actions/runs/39736485493
Сборка релиза: https://github.com/rangerxxyy/nfqws2-ui/actions/runs/39736592506

Это аудит полноты исходного задания, а не утверждение о завершении всех функций.
Состояние опубликованного релиза проверено через GitHub API: обычный релиз,
не draft и не prerelease; установщик, ARM64-архив и SHA-256 загружены.
CI и release workflow завершились успешно. Это не проверка на маршрутизаторе.

## Подтверждённая архитектура и интерфейс

- `web/src/App.tsx` содержит перенесённую разметку, `panel.css` — стили,
  `panel.ts` — обработчики. TypeScript API-клиент отделён в `api.ts`.
- `backend/src/main.rs` обслуживает API и создаёт минимальную HTML-оболочку
  для загрузки собранного JavaScript. Исходного `web/index.html` нет.
  Браузер всё равно получает HTML-документ: это необходимая часть веб-приложения.
- Удаление авторизации выполнено по прямому указанию пользователя и заменяет
  противоречащие этому пункты приложенного задания.
- Точное визуальное соответствие всех экранов исходному HTML на разных
  разрешениях не доказано. Структурные проверки TSX не заменяют сравнение рендера.

## Кнопки и настоящие методы

| Элемент | Frontend → Rust API | Состояние и предел доказательства |
|---|---|---|
| Статус, RAM, CPU, версии | `GET /api/status` | Системные счётчики и состояние службы; CPU по разнице измерений, RAM по данным ядра. Номинальные 512 МБ не подставляются вместо `MemTotal` |
| Включить, выключить, перезапустить | `POST /api/service` → фиксированный init script/action | Реальные команды службы; при restart показывается анимация. Проверка на конкретном устройстве не выполнена для v0.1.8 |
| Загрузить/редактировать конфиг | `GET/PUT /api/config` | SHA-256 revision, backup, атомарная запись, повторное чтение. PUT не применяет конфиг к процессу |
| Сохранить и применить | `POST /api/nfqws2/apply` → `apply_config_transaction` | Запись, повторное чтение, restart, восстановление и повторный restart при ошибке. Нет независимого сетевого rollback по таймауту и сверки полного активного argv |
| Выбор интерфейса и режима | `updateConfigVariable` → конфиг → Apply | Интерфейсы берутся из discovery; доступны непустые MODE-переменные загруженного конфига. Нет отдельного серверного редактора профилей |
| Сведения о путях и модулях | `GET /api/nfqws2/installation` | Конфиг, кандидаты init/binary, интерфейсы, ссылки Lua/blob и признаки доступа. Полная связь профилей с активным процессом не реализована |
| Выбор пяти списков | `GET /api/nfqws2/lists`, `GET /api/nfqws2/lists/{id}` | Существующие разрешённые файлы; ссылки из argv или конфига. Неоднозначные и динамические пути не разрешаются произвольно |
| Добавить/удалить/найти/импорт/экспорт/дубликаты | Локальный черновик `list-editor.ts` | Для записи требуется кнопка сохранения; экспортирует текущий черновик |
| Сохранить список | `PUT /api/nfqws2/lists/{id}` → `put_list` | Валидация, revision, backup, атомарная запись и чтение. Автоматическое применение списка службой отсутствует |
| Создать/восстановить снимок | `GET/POST /api/backups`, `POST /api/backups/{id}/restore` | Копии конфигурации; нет полного снимка всех зависимых списков и автоматического расписания |
| Журналы | `GET /api/logs` | Ограниченный хвост разрешённых журналов; учитывается буквальный `LOG_DEBUG_PATH`. Динамические shell-выражения не исполняются |
| Версия панели → выбор релиза → установить | `GET /api/updates/releases`, `POST /api/updates/install` | Реальные Releases, SHA-256, отдельный updater, переключение symlink, HTTP health-check и откат |
| Версия nfqws2 → выбор релиза → установить | `GET /api/nfqws2/updates/releases`, `POST /api/nfqws2/updates/install` | Реальные Releases `nfqws/nfqws2-keenetic`, digest GitHub, opkg, пакет предыдущей версии для отката. Только Entware aarch64-3.10 |
| Состояние обновления и уведомление снизу | `GET /api/updates/operations/{id}` | Отображает состояние операции updater-а; не подменяет результат таймером |
| Диагностика сайта | `runSiteDiagnosis` → `POST /api/nfqws2/diagnostics/site` | Ограниченные реальные DNS/DoH/TCP/HTTP(S)/SNI/route/list-пробы с тайм-аутами и pinning публичных IP подключены (v0.1.11); полный bypass-сравнитель с nfqws2 и доказательная проверка блокировки не реализованы |
| Автоподбор и применение стратегии | `startStrategyAutoScan`, `applyStrategyToConf` отключены | Backend управления стратегиями/профилями не реализован; доступно ручное редактирование конфигурации |
| Telegram, community/ASN, NAS, полный экспорт | Соответствующие действия в `DISABLED_PANEL_ACTIONS` | Backend не реализован |

## Проверка требований приложенного задания

| Раздел задания | Доказательство / оставшаяся работа |
|---|---|
| 1. Аудит upstream | Ревизии и исходные наблюдения записаны в `BACKEND_GAP_ANALYSIS.md`, `UPSTREAM_ANALYSIS.md`. Старые таблицы необходимо читать с учётом этого аудита |
| 2. Полное discovery | Частично: реальные кандидаты и доступы есть. Нет полного детектора пакета/всех профилей и доказательства активного конфига на целевом устройстве |
| 3. CRUD всех списков | Чтение, изменение черновика, сохранение и отрицательные тесты есть. Нет связи каждого списка с активными профилями, полноценной защиты от внешней записи nfqws2 между проверкой revision и rename |
| 4. Стратегии и профили | Не завершено: отсутствуют серверный сохраняющий парсер, CRUD профилей, версия-зависимая валидация Lua/флагов и подтверждение запуска с выбранным argv |
| 5. Режимы и системные настройки | Частично через редактирование реального конфига. Отдельная проверка политик, маршрутов, диапазонов портов и reload-возможностей отсутствует |
| 6. Реальные endpoints | Опубликованные маршруты имеют обработчики. Предложенные профили/стратегии/runtime/validate/rollback API в полном виде отсутствуют |
| 7. Все страницы UI | Не завершено: перечисленные выше действия отключены. Статические примеры и состояния неподключённых страниц требуют отдельного просмотра перед заявлением полного переноса |
| 8. Транзакции и откат | Откат конфигурации при ошибке restart есть. Многофайловая транзакция, предварительная проверка установленным бинарником и независимый сетевой timeout rollback отсутствуют |
| 9. Диагностика и тесты | CI проверяет существующие Rust/TS/shell сценарии. Нет end-to-end проверки полного задания с настоящим nfqws2, всех разрешений/гонок/профилей и пиксельного сравнения |
| 10. Публикация | v0.1.8 опубликован; установщик, ARM64 musl архив и checksum присутствуют. Другие архитектуры не заявлены этим пакетом |
| 11. Полный путь на Keenetic без SSH | Не доказан: ручное редактирование работает через API, но выбор стратегии и полный цикл version-aware validation/runtime verification ещё отсутствуют |

## Следующие обязательные этапы

1. Серверный парсер конфигурации, сохраняющий исходные диапазоны текста,
   комментарии, кавычки и неизвестные переменные; неподдерживаемые выражения
   должны возвращать точную диагностику, без `source`/`eval`.
2. На его основе — inventory/редактор профилей и стратегий TCP/UDP/QUIC,
   предварительный diff и проверка совместимости установленным бинарником.
3. Транзакция всех затронутых файлов, проверка процесса после применения,
   независимое восстановление сетевых настроек по таймауту.
4. Подключение оставшихся страниц, затем полный визуальный и runtime-аудит.
5. Разрешённая проверка на целевом Keenetic с резервными копиями и протоколом
   чтение → изменение → запись → повторное чтение → применение → откат.

Полная исходная цель остаётся незавершённой. Публикация базового релиза сама
по себе не подтверждает реализацию всех пунктов приложенного задания.

## Дополнение после базового аудита

Релизы v0.1.9–v0.1.11 добавили обнаружение списков, метрики Keenetic RCI,
lossless preview простых присваиваний, первую реальную диагностику сайта,
компактную шапку и обновлённый список. `GET /api/nfqws2/runtime` добавлен в
рабочую ветку: он читает argv проверенного процесса, выделяет группы `--new`
и возвращает безопасную сводку. Проверка профилей подтверждает только состав
командной строки, не эффективность обработки трафика.

Эти изменения не закрывают CRUD стратегий/профилей, валидацию кандидата
установленным бинарником, многофайловое применение и сетевой rollback. Для
этого нужна дальнейшая работа и проверка на целевом устройстве; Windows-тесты
и CI не выдаются за проверку Keenetic.
