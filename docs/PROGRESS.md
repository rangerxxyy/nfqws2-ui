# Журнал прогресса

## 2026-10-21 — подготовка v0.1.3

- Рабочая копия заменяет React shell на сохранённую структуру приложенного HTML-макета и контроллер на TypeScript; форма входа не блокирует стартовый экран и вынесена в отдельный раздел бокового меню.
- Удалены Tailwind/Google Fonts CDN и все inline event handlers; CSS и шрифты собираются локально для работы под CSP Rust backend.
- Исправлена потеря одного из действий при двух событиях на одном поле (input/scroll). Контроллер теперь разбирает действия по типу события; текущие макетные возможности без endpoint явно отключаются.
- Новые тесты проверяют меню авторизации, отсутствие старого login-shell/CDN/inline-handler, повторных атрибутов и неприкреплённых действий.
- Локально прошли frontend tests (6), production build и `pnpm audit --prod`; Rust fmt, 15 Rust tests, clippy и `cargo audit` прошли.
- ShellCheck 0.11.0, `dash -n` и installer preflight прошли после исправления комментариев trap suppression. Полный BusyBox symlink regression требует Linux BusyBox и будет проверен GitHub CI.
- Production preview открыт в браузере; структура меню, отдельный пункт авторизации, конфигурация и локальные CSS/JS assets загружены. На этом ПК нет Linux linker (`cc`) для ARM64 musl, поэтому целевой бинарник и аппаратная совместимость ещё не подтверждены; это проверит release workflow.
- Release-mode Rust backend локально обслужил production UI: HTTP health/root=200, CSP присутствует, анонимный status=401, тестовый login/CSRF/session проходят. На Windows сервис ожидаемо классифицирован как `unknown`; тестовые API не запускали start/stop и не меняли конфигурацию nfqws2.
- Новый релиз пока не опубликован; версия v0.1.3 подготовлена только после прохождения оставшихся CI/release gates.

- При первоначальной проверке SSH к роутеру не прошёл publickey/password аутентификацию; последующий доступ подтвердился ключом `keenetic_ed25519` по SSH-порту 222.
- Реализованы TypeScript/React UI, Rust API, auth+CSRF, статус и метрики, allowlisted config/backups, логи, port selection/persistence, обновляемый install/uninstall и Entware init integration.
- Первый установочный пакет ограничен ARM64 Entware; под `zemidala/nfqws2-ui` у текущего аккаунта только чтение, создан будет независимый новый репозиторий пользователя.
- Локальная проверка пройдена: Rust 14 тестов, Clippy, TypeScript 5 тестов и prod build, HTTP smoke; `dash -n` прошёл.
- Cross-target `cargo check` сначала нашёл Unix-only async compile issue; исправлено, повторный `aarch64-unknown-linux-musl` check прошёл.
- После публикации v0.1.1 на Keenetic (aarch64) выполнен изолированный smoke-test точного release-архива из `/tmp`: SHA-256 совпал, ARM64-бинарник сообщил версию 0.1.1, `/api/health` и `/` вернули HTTP 200, анонимный `/api/status` вернул 401, вход тестовым временным паролем и авторизованный `/api/status` прошли; сервис выбрал порт 1003. Реальный UI smoke-test выполнен через HTTP-корень, но пиксельное сравнение интерфейса с HTML-прототипом и его перенос ещё не сделаны.
