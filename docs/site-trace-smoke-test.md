# Smoke-test трассировки на роутере

Локальные тесты не запускают `iptables` и не проверяют сетевой путь роутера. Этот сценарий выполняется отдельно после установки сборки с Rust backend на Keenetic/OpenWrt.

Предварительная проверка backend требует mangle hooks `PREROUTING`, `OUTPUT` и `POSTROUTING`. Она не анализирует init-скрипт: правила трассировки добавляются только в собственные временные цепочки и удаляются точными командами.

1. Откройте панель с компьютера и убедитесь, что основной `nfqws2` работает.
2. Откройте самостоятельный раздел **Трассировка**. Проверьте HTTPS на заведомо доступном домене, например `example.com`.
3. Убедитесь, что появились независимые результаты «Без nfqws2» и «С nfqws2», выбранный публичный IPv4 и журнал `--debug`. Для HTTP повторите тест с протоколом HTTP.
4. Если Keenetic использует политику доступа «только устройства политики», проверьте домен через неё. Backend должен сохранить policy mark для тестового исходящего соединения; основной nfqws2 не должен обработать ни базовый запрос, ни тестовый запрос второй раз.
5. Проверьте домен, которому на этой сети нужен обход. Сравните оба результата и журнал профиля; HTTP 4xx/5xx означает, что сервер ответил, и не считается сетевой недоступностью.
6. Проверьте отказ для `router.local` или `127.0.0.1`: запрос должен быть отвергнут до сетевых проверок.
7. После завершения обновите статус службы и убедитесь, что основной `nfqws2` остался запущен, конфигурация и списки не изменились.

При неоднозначном владельце firewall, занятой тестовой очереди или неудачной очистке backend должен показать техническую ошибку/недоступность, не утверждая, что сайт заблокирован. Не очищайте системные цепочки вручную для прохождения теста.

Подтверждать smoke-test выполненным можно только после запуска на целевом роутере.
