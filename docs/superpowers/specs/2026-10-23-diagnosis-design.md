# Диагноз доступности и результаты трассировки

Запрос пользователя: сохранить стиль панели, сравнивать запрос мимо nfqws2 с текущим доступом; перенести механизм QUIC из reference backend; показывать понятные итоги трассировки. Пользователь ранее явно поручил выполнять изменения и проверки без промежуточного согласования.

Подход: Rust продолжает обслуживать текущий endpoint диагностики. Добавляются структурированные direct/current пробы и QUIC comparison; TypeScript рисует итог и подробности. Альтернатива curl-only непригодна для роутеров без HTTP3. Полный новый HTTP3 стек избыточен: переносится MIT Lua QUIC Initial, запускаемый установленным nfqws2 с --intercept=0. UDP-ответ подтверждает QUIC, но не полный HTTP3 ответ. При доступном HTTP3 curl выполняется полноценный запрос. Alt-Svc служит отдельным признаком объявленной поддержки.

Контракт: DiagnosticReport сохраняет host/addresses/steps/summary/limitations и добавляет direct,current (DiagnosticStep) и quic (null либо {direct,current,method:'quic_initial'|'http3',http3Advertised:boolean|null}). direct всегда использует временный bypass и проверочный порт; current отправляется после удаления bypass через обычный маршрут роутера. Техническая невозможность изоляции — unavailable, а не блокировка. Трассировка сохраняет API; результат рисуется по каждому TracePhase, включая неизвестный этап и HTTP ошибки.

Изоляция: только публичный IPv4, один адрес/порт, диапазон исходящих портов 40000:40999, уникальные цепочки, точное удаление, общий lock диагностики и трассировки. Основной демон не останавливается. Сетевые пробы ограничены временем и объёмом. Автоматический POST пользовательским сайтам из reference не переносится: GET и ограниченное чтение достаточны для запрошенного сравнения доступности.

Проверки: реальные UDP loopback тесты отправки/ответа и timeout, привязка QUIC ответа к CID, проверка захвата stderr, тесты правил bypass TCP/UDP, матрица verdict и отображения неизвестных/ошибочных HTTP результатов, полные Rust/frontend suites и сборка. Реальный Keenetic без SSH не может считаться проверенным.
