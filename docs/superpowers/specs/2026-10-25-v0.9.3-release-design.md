# v0.9.3 Release Design

## Intent

Ship the verified work on the existing v0.9.2 line as nfqws2-UI v0.9.3, retaining the unfinished help-report work already present in this checkout.

## Goals

- Keep each configuration result disclosure independently open or closed while the UI polls for progress.
- Show per-domain successful attempts and average successful probe time, following current Zemidala `ok` / `tries` / `ms` behavior.
- Finish and describe the privacy-conscious help report already present in the worktree.
- Align backend/frontend version metadata, changelog, release notes, and GitHub release workflow.
- Publish only after the complete test and package verification succeeds.

## Constraints

- Preserve all existing working-tree edits; no reset or cleanup of unrelated files.
- Maintain fail-fast retry behavior and existing config apply safeguards.
- Keep the release archive format, installer, rollback, and target architecture unchanged.
- Zemidala v1.22.3 is the comparison reference; its recent 1.22.3 changes outside config testing are not copied.

## Approach

Use the existing GitHub tag-triggered workflow and `RELEASE_v0.9.3.md` as the source of release body via `body_path`. Verify locally, push the release commit and tag, then confirm GitHub Actions produced the release assets.

## Acceptance

- Frontend, Rust, shell/package checks pass.
- Release files consistently identify v0.9.3 and the release body contains only v0.9.3 notes.
- The tagged workflow produces the AArch64 musl archive, installer, and SHA-256 file.
