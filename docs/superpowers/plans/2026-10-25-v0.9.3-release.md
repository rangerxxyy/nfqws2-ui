# nfqws2-UI v0.9.3 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a verified nfqws2-UI v0.9.3 release containing the configuration-results fixes and the in-progress help report.

**Architecture:** Retain the current single Rust backend and TypeScript frontend. Keep GitHub's tag-triggered AArch64 musl release workflow and load release notes from the versioned release markdown file.

**Tech Stack:** Rust, Axum, TypeScript, React template, pnpm/Vitest, GitHub Actions, shell packaging.

**Spec:** `docs/superpowers/specs/2026-10-25-v0.9.3-release-design.md`

## Global Constraints

- Preserve existing user edits and the current release branch.
- Keep foreign-config probing sequential and stop retries on the first failure.
- Preserve the current tarball layout, rollback semantics, and aarch64-unknown-linux-musl target.

## Review Focus

- Poll updates must not reset each disclosure independently.
- Failed and partial probes must report actual tries, successes, and successful-only average time.
- Older persisted operations without new metrics must still render sensibly.
- The GitHub release description must load the v0.9.3 notes, not the previous workflow's hard-coded text.
- The release tag must point at the verified v0.9.3 commit.
