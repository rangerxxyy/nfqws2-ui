# Apply Confirmed nfqws2 Strategy Implementation Plan

> **For agentic workers:** Execute inline as authorized by the user. Use TDD for each behavior and verify before commit.

**Goal:** Let a user preview and explicitly apply only a twice-confirmed strategy, verify the live service and target site, and restore the prior state on failure.

**Architecture:** Rust owns selection, config/list mutation, dry-run, backup, restart, health probe and rollback. It re-reads the persisted pick and current revisions at both preview and apply. A proven existing profile/list is preferred; if the runtime relationship cannot be proved, the backend builds one domain-scoped `NFQWS_ARGS_CUSTOM` profile. TypeScript displays the exact diff and sends only operation/candidate/revision identifiers.

**Tech Stack:** Rust 2024, Tokio, Axum, existing TypeScript/React/Vite UI and Vitest.

**Spec:** `docs/superpowers/specs/2026-10-23-strategy-application-design.md`; source behavior: `docs/ZEMIDALA_AUTOPICK_ANALYSIS.md`.

## Global Constraints

- Only terminal pick operations with `confirmed == true` are eligible; browser-supplied strategy tokens are never trusted.
- QUIC application remains unsupported until a real isolated QUIC strategy runner exists.
- Config/list writes are revision-checked, backed up, bounded and serialized; rollback must not overwrite concurrent edits.
- If `NFQWS_ARGS_CUSTOM`, profile ordering, list ownership or active state is ambiguous, refuse the optimization or application with a clear error.
- Never run the router's firewall or service commands on the developer machine; use injected callbacks/temp files in tests.

## Review Focus

- A client cannot substitute arbitrary strategy steps or choose an unconfirmed candidate; test unknown IDs, index bounds and unconfirmed results.
- Stale config/list revisions cause no write or restart; test both targets.
- Dynamic/duplicate `NFQWS_ARGS_CUSTOM` or ambiguous active profile ordering is rejected; test shell expressions, quoting and duplicate assignments.
- A failed dry-run leaves files and service untouched; a failed restart/site check rolls back only if the candidate revision is still current; test each branch.
- Successful hostlist optimization is selected only when the exact active profile, protocol, list path, missing domain and precedence are proven; otherwise test fallback to a host-only profile.
