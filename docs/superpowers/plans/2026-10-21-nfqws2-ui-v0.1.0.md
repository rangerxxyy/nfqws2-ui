# План реализации nfqws2-ui v0.1.0 с нуля

## Инварианты

- Не восстанавливать и не клонировать удалённый репозиторий в новый проект.
- Сохранить старую локальную копию нетронутой и использовать только для сравнения поведения.
- TypeScript + Rust — основа; Shell только install/uninstall.
- Тесты и измеримые проверки до заявлений о готовности.
- Управлять nfqws2 только через штатный init script; пока доступ SSH не подтверждён, роутер не трогать.

## Этапы

1. **Документы и тестовые контракты:** upstream/design/goal/architecture зафиксированы; Rust tests для статуса службы, PID и безопасного port selection написаны и сначала показывают ожидаемый провал.
2. **Rust backend:** typed service discovery/action, login/session/CSRF, allowlisted config IO + atomic backup/restore, bounded log tail, status and system metrics.
3. **TypeScript UI:** React/Vite, exact visual direction, overview status and action controls, config editor with unsaved guard, backup/log panels, responsive menu, i18n skeleton ru/en/zh/tr.
4. **Integration:** static UI served from Rust, API contract tests, auth/session checks, mockable service adapter only for tests.
5. **Installer:** POSIX/BusyBox-compatible, dependency/platform detection, port 1002 then bounded next-available selection, checksum, backup/rollback, no unrelated service changes.
6. **Quality gates:** formatting, Rust unit/integration tests, TS typecheck/build, shell syntax/static checks, package checksums, install/uninstall dry-run; router smoke only if SSH is accessible.
7. **Fresh GitHub repo and release:** create `rangerxxyy/nfqws2-ui` as new public repository after implementation/package gates, publish only verified artifacts, then fetch release/assets back for verification.

## Acceptance gates

- Service status distinguishes running/stopped/error/unknown; no green on command failure.
- Admin actions cannot accept arbitrary shell or paths.
- Config write creates recoverable backup before atomic replacement.
- Login/session/CSRF checks are enforced on mutations.
- Build/test/documentation accurately state target architecture/device smoke limitations.
- Release only after all artifacts match tested hashes; otherwise report the exact blocker and keep source ready locally.
