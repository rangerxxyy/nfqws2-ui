# nfqws2-ui v0.6.0 UX Implementation Plan

> **For agentic workers:** Native inline execution is explicitly requested by the user. Follow the repository's existing TypeScript/Rust patterns and commit each completed block.

**Goal:** Implement and publish nfqws2-ui v0.6.0 with all 13 requested UI and behavior improvements.

**Architecture:** Preserve the existing React markup and delegated TypeScript handlers. Extend existing shared UI utilities and CSS; keep backend behavior unchanged unless a requirement demonstrates a backend gap. Reuse the existing site diagnosis and update APIs.

**Tech Stack:** React, TypeScript, Tailwind/CSS, Vitest, Rust/Axum, Cargo, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-24-v0.6.0-ux-design.md`

## Global Constraints

- Complete all 13 requested changes in the specified order.
- Preserve existing start/stop and update operations; reflect service state accessibly.
- Keep release notes limited to v0.6.0 changes.
- Avoid router stress tests, batch probes, restarts, and installation during validation.
- Retain all sections in mobile navigation.
- Sanitize Markdown descriptions; do not render raw HTML from release content.

## Review Focus

- nfqws2 status changes while the header is rendered: icon, label, and action must stay in sync.
- Release descriptions containing links, inline code, HTML, and malformed Markdown must render safely.
- Telegram mode changes and saved settings must not expose proxy/interface fields for direct mode.
- Diagnosis failure/cancellation must not leave an animated stage stuck as running.
- Mobile navigation and layout must preserve all sections without horizontal overflow.
