# Strategy Autopick and 16KB Diagnosis Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add real, cancellable strategy testing and repeatable 16–20 KB transfer diagnosis to the existing nfqws2-ui Rust + TypeScript application.

**Architecture:** Port the safe behavior of Zemidala’s sequential candidate workflow into native Rust services. Reuse the existing trace isolation primitives and persisted-operation patterns, add bounded byte-count probes and a typed frontend client, then add UI states that render only backend results. Config apply, auto-apply, unmeasured parallelism, and unvalidated community catalogs remain outside this stage.

**Tech Stack:** Rust 2024, Tokio, Axum, Serde; TypeScript, React, Vite, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-23-autopick-16kb-design.md`

## Global Constraints

- Preserve project name `nfqws2-ui`, current frontend style, and existing Rust + TypeScript architecture.
- Never mutate the main nfqws2 config/service automatically.
- Do not launch tests unless host and strategy validation pass; never run tests against private/local targets.
- Never use a fixed NFQUEUE, globally shared temporary chain names, or broad process matching to clean test resources.
- Keep candidate testing sequential until device RAM/CPU measurements justify concurrency.
- Mark router-only acceptance cases unverified without a real Keenetic device.

## Review Focus

- Unknown or missing active process args must block isolated strategy startup; test that startup refuses without a complete verified argv.
- Cancellation during DNS/connect/read must persist cancelled and release owned resources; test cancellation during each async phase.
- A server that returns a short complete body must not be classified as a 16 KB stall; test short-complete and repeated boundary-stall fixtures.
- An unsupported Lua function or argument must be rejected before NFQUEUE/firewall setup; test with missing function metadata.
- Corrupt or oversized persisted task history must be rejected/pruned without panic; test invalid JSON and bounds.
