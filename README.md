# nfqws2-ui

Локальная панель управления службой nfqws2 для Keenetic с Entware на TypeScript и Rust. Shell используется только для установки, удаления и init-интеграции.

## Установка

Первый релиз предназначен для 64-битных ARM-устройств Entware. Нужны `wget`, `tar` и `sha256sum` (Entware: `coreutils-sha256sum`). Если `sha256sum` отсутствует, установите зависимость отдельно командой `opkg update && opkg install coreutils-sha256sum`. Установщик не меняет состояние пакетов Entware. Он скачивает архив релиза, сверяет SHA-256, сохраняет конфигурацию и проверяет HTTP health endpoint.

```sh
wget -qO- https://github.com/rangerxxyy/nfqws2-ui/releases/latest/download/install.sh | sh
```

После установки консоль напишет «Панель успешно установлена», покажет фактический выбранный порт и кликабельные URL с IPv4-адресами сетевых интерфейсов роутера. Порт начинается с 1002; если он занят, backend выбирает следующий свободный до 1100. Выбранный порт хранится в `/opt/var/run/nfqws2-ui.port`.

Обновление выполняется той же командой. Резервные копии сохраняются. При ошибке запуска/HTTP-проверки установщик возвращает предыдущую версию. Удаление панели: `/opt/share/nfqws2-ui/current/uninstall.sh`; `--purge` также удаляет резервные копии панели. Конфигурация nfqws2 не удаляется.

В панели версии обновляются раздельно: кнопка `nfqws2-UI` показывает релизы этой панели; кнопка `nfqws2` показывает реальные версии upstream-пакетов `nfqws/nfqws2-keenetic`. Установка ядра в этом выпуске поддерживает Entware `aarch64-3.10`: Rust проверяет GitHub SHA-256 digest, затем запускает `opkg install` и перезапускает штатную службу; при неуспехе пытается установить предыдущую версию пакета.

В шапке кнопки перезапуска и остановки находятся слева рядом со статусом. В группе версий слева расположен `nfqws2`, справа — `UI`.

RAM и CPU на Keenetic читаются из локального RCI (`http://127.0.0.1:79/rci/show/system`), как в XKeen UI: общий объём берётся из `memtotal`, занятый — из `memory`, CPU — из `cpuload`. Если RCI требует токен, используется `NFQWS2_UI_RCI_TOKEN` из окружения backend или существующий `xkeen.rci_token` из `/opt/etc/xkeen/xkeen.json`; токен не возвращается в API. При недоступности RCI используются счётчики Linux; источник виден в подсказке RAM. Значение 512 МБ не подставляется искусственно.

Существующие `user.list`, `auto.list`, `exclude.list`, `ipset.list` и `ipset_exclude.list` доступны из штатного каталога `lists` рядом с обнаруженным конфигом, даже когда выбранный режим не ссылается на них. Явный путь из процесса или конфига имеет приоритет; файлы не создаются автоматически. Наличие списка не означает, что текущий профиль его использует.

## Сборка и проверки

Требуются Rust stable, Node.js 22 и pnpm 10.

```sh
cargo fmt --manifest-path backend/Cargo.toml --all -- --check
cargo test --manifest-path backend/Cargo.toml --locked
cargo clippy --manifest-path backend/Cargo.toml --all-targets --locked -- -D warnings
pnpm --dir web install --frozen-lockfile
pnpm --dir web test
pnpm --dir web build
```

Для статического ARM64 Linux-артефакта используется `cross` с target `aarch64-unknown-linux-musl`. Публичный релиз публикуется GitHub Actions только после прохождения Rust, frontend и target-тестов.

## Безопасность и ограничения

- Вход, пароль, сессии и CSRF удалены из UI и backend по запросу пользователя. Панель слушает `0.0.0.0`, а API управления доступен без авторизации: ограничьте доступ к LAN-подсети и firewall роутера, не публикуйте порт панели в интернет.
- Действия сервиса вызывают только штатный init-скрипт nfqws2; произвольные shell-команды из API не принимаются.
- Быстрый выбор `ISP_INTERFACE` заполняется из `/sys/class/net` на устройстве; если backend не обнаружил интерфейсы, быстрый выбор отключён, а фактическое значение остаётся видимым в raw-конфиге. Имена интерфейсов не подставляются из шаблонов.
- Для конфигурации разрешён только `nfqws2.conf`; перед записью создаётся резервная копия, проверяется ревизия, файл заменяется атомарно.
- Резервные копии панели: `/opt/var/lib/nfqws2-ui/backups`; журнал панели: `/opt/var/log/nfqws2-ui.log`. Установщик удаляет оставшийся файл пароля от прежних версий.
- Первый релиз предназначен для ARM64 Entware. OpenWrt/procd и другие архитектуры не объявляются поддержанными до отдельных сборочных и аппаратных проверок.
- Rust отдаёт загрузочную HTML-оболочку маршрута `/`, а файлы интерфейса собираются из TypeScript/TSX. Исходной HTML-страницы и `web/index.html` в проекте нет. Проверка реального управления nfqws2 на роутере выполняется отдельно после установки.
