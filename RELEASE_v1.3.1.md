# v1.3.1 — Полировка UI/UX и фиксы разделов

Рабочий журнал релиза. Публикация выполняется только после завершения и проверки всех 11 пунктов.

## Пункт 1. Копирование конфигурации и кнопки разделов

- Кнопка «Копировать» берёт актуальный текст из `#nfqwsConfTextarea`, использует общий `writeTextToClipboard` с fallback через временный textarea и показывает уведомление об успехе или ошибке.
- Кнопка копирования скрывается вне подраздела «Конфигурация»; выбран вариант скрытия, потому что копировать содержимое редактора в настройках и скриптах неуместно.
- «Применить конфигурацию» остаётся в общей панели подразделов и доступна в редакторе, настройках и скриптах.
- Проверено: `panel-template.test.ts` (точечный тест), TypeScript typecheck; локально в Chromium проверены видимость кнопок в редакторе и настройках и возврат кнопки при переключении обратно.
- Ограничение: не проверял изменение системного буфера обмена в браузере; код использует актуальное значение редактора и общий fallback.

## Пункт 2. Переключение ISP_INTERFACE

- Сохранён выбор обнаруженных интерфейсов. Если backend не вернул ни одного интерфейса, вместо пустого disabled-select показывается поле ручного ввода.
- Имя проверяется перед запросом: 1–15 символов, разрешены типичные символы Linux-интерфейса; пустая строка, пробелы, slash, shell-синтаксис и `.`/`..` отклоняются. Ошибочный ввод сбрасывается к текущему значению.
- Оба контроля вызывают Rust preview API; после изменения значение остаётся в черновике, применяется общей командой сохранения/перезапуска и повторно выбирается из конфига при следующей загрузке.
- Проверено: 320 frontend-тестов, TypeScript production build; Chromium показал текущее значение `eth0`, доступный список, скрытое ручное поле при обнаруженных интерфейсах, видимую кнопку применения и отсутствие ошибок консоли. Проверки Rust-кода не требовались: backend не менялся, существующий preview endpoint уже включает `ISP_INTERFACE` в allowlist и безопасно кодирует значение.
- Ограничение: среда local mock обнаружила `eth0`, поэтому ветка без обнаруженных интерфейсов покрыта логикой/тестом, но визуально на устройстве без интерфейсов ещё не проверена.

## Пункт 3. Удаление отключённого справочника флагов

- Удалена карточка «Справочник флагов nfqws2» с поиском и пустой областью результата из настроек конфигурации.
- Удалён связанный обработчик `filterDocs`; поиск по исходникам больше не находит `docItemsContainer` и runtime-ссылок на этот блок. Отдельных стилей/локалей только для него не было.
- Проверено: 321 frontend-тест, production build; в Chromium справочник отсутствует, карточка групп аргументов и «Применить конфигурацию» видны, ошибок консоли нет.

## Пункт 4. Переименование профиля

- В заголовке каждого профиля добавлена компактная кнопка-карандаш с доступным названием «Изменить название профиля».
- Открывается UI-диалог с проверкой непустого имени (буквы/цифры/точка/дефис/подчёркивание, до 32 символов). Escape, фокус и закрытие по фону обеспечиваются нативным modal `<dialog>`.
- Имена пользовательских профилей сохраняются как `--name` в черновике соответствующего `NFQWS_ARGS_CUSTOM`; штатные имена сохраняются локально в браузере и не меняют общие аргументы/правила nfqws2. Имя сразу обновляется и в списке профилей.
- Проверено: сначала добавлен тест, подтвердивший отсутствие функции; затем 322 frontend-теста прошли, production TypeScript/Vite build прошёл. В Chromium проверены открытие окна, успешная смена имени пользовательского профиля, сохранение имени штатного QUIC и возврат тестового названия; ошибок консоли не обнаружено.
- Ограничение: переименование встроенных групп — локальная подпись интерфейса для текущего браузера, так как изменение её в конфиге затронуло бы общие штатные параметры.

## Пункт 5. Удаление «QUIC по сайтам» из конструктора

- В `prepareVisibleRuntimeProfiles` исключена отдельная навигационная карточка «QUIC по сайтам»; счётчик теперь отражает реально показанные карточки, а последующие профили перенумеровываются.
- API, конфигурационные переменные и общие параметры не удалялись: они по-прежнему могут обслуживать сайты вместе с другими группами nfqws2.
- Проверено: целевой тест сначала падал из-за видимой карточки, затем все 322 frontend-теста прошли, production build прошёл. В Chromium список сократился с пяти карточек до четырёх; «QUIC по сайтам» не отображается, HTTP/HTTPS по сайтам остаётся доступен.
- Решение: справка о совместном использовании общих переменных оставлена, так как она объясняет область действия изменений в соседнем профиле.

## Пункт 6. Полные подписи файлов списков

- Стандартные вкладки теперь показывают читаемую подпись и имя файла: например, «Пользовательские домены» / `user.list`; аналогично оформлены все пять штатных файлов.
- Пользовательские `.list` получают подпись «Пользовательский список» и полное имя файла. Заголовок выбранного файла также отображает подпись и имя.
- Layout разрешает перенос длинных названий и имён, вкладки остаются горизонтально прокручиваемыми на узких экранах; убрано ограничение ширины/ellipsis у текущего имени файла.
- Проверено: 323 frontend-теста, production build; Chromium показывает все полные подписи и filenames без обрезки. Список в локальном mock отсутствует, поэтому значения вкладок disabled, но их текст проверен в DOM.
