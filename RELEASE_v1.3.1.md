# v1.3.1 — Полировка UI/UX и фиксы разделов

## Изменения

1. Копирование актуальной конфигурации и доступность кнопок «Копировать»/«Применить».
2. Переключение `ISP_INTERFACE` с сохранением выбранного значения.
3. Удаление «Справочника флагов nfqws2» из настроек конфигурации.
4. Переименование профиля в «Конструкторе стратегий».
5. Удаление «QUIC по сайтам» из списка конструктора.
6. Полные подписи `.list` с именами файлов.
7. Общий стиль кнопок и состояний выбора по референсу XKeen UI.
8. Метка `NFQWS_ARGS_CUSTOM` или соответствующей переменной под названием профиля.
9. Удаление лишних подсказок из «Списков доменов и IP».
10. Общие токены шрифта, палитры и типографической иерархии.
11. Доступные UI-диалоги вместо браузерных подтверждений.

Тестирование проведено на ПК (Chromium и Firefox) и роутере. Конфигурация не менялась, nfqws2 не перезапускался.

## Пункт 4. Переименование профиля

- Проверено: сначала добавлен тест, подтвердивший отсутствие функции; затем 322 frontend-теста прошли, production TypeScript/Vite build прошёл. В Chromium проверены открытие окна, успешная смена имени пользовательского профиля, сохранение имени штатного QUIC и возврат тестового названия; ошибок консоли не обнаружено.

## Пункт 5. Удаление «QUIC по сайтам» из конструктора

- В `prepareVisibleRuntimeProfiles` исключена отдельная навигационная карточка «QUIC по сайтам»; счётчик теперь отражает реально показанные карточки, а последующие профили перенумеровываются.
- API, конфигурационные переменные и общие параметры не удалялись: они по-прежнему могут обслуживать сайты вместе с другими группами nfqws2.
- Проверено: целевой тест сначала падал из-за видимой карточки, затем все 322 frontend-теста прошли, production build прошёл. В Chromium список сократился с пяти карточек до четырёх; «QUIC по сайтам» не отображается, HTTP/HTTPS по сайтам остаётся доступен.
- Решение: справка о совместном использовании общих переменных оставлена, так как она объясняет область действия изменений в соседнем профиле.

## Пункт 6. Полные подписи файлов списков

- Стандартные вкладки теперь показывают читаемую подпись и имя файла: например, «Пользовательские домены» / `user.list`; аналогично оформлены все пять штатных файлов.
- Пользовательские `.list` получают подпись «Пользовательский список» и полное имя файла. Заголовок выбранного файла также отображает подпись и имя.
- Layout разрешает перенос длинных названий и имён, вкладки остаются горизонтально прокручиваемыми на узких экранах; убрано ограничение ширины/ellipsis у текущего имени файла.
- Проверено: 323 frontend-теста, production build; Chromium показывает все полные подписи и filenames без обрезки. Список в локальном mock отсутствует, поэтому значения вкладок disabled, но их текст проверен в DOM.

## Пункт 7. Кнопки в едином стиле

- Кнопки панели списков приведены к единой компактной типографике и форме: вторичные действия, основное применение, опасное удаление; активный вид отмечается по `aria-pressed`.
- Добавлены явные состояния hover, active, focus-visible, disabled и selected с акцентным цветом темы. Стили ориентированы на семантические default/outline/destructive варианты кнопок XKeen UI.
- Проверено: 324 frontend-теста и production build прошли; тест покрывает варианты кнопок и ключевые состояния в CSS. Логика действий и обработчики не менялись.

## Пункт 8. Метка переменной аргументов профиля

- Под заголовком каждого профиля показывается используемая переменная конфигурации. Для пользовательского профиля — `NFQWS_ARGS_CUSTOM`, для штатного — источник первичного редактируемого компонента (например, `NFQWS_ARGS_UDP` или `NFQWS_ARGS_QUIC`).
- Это особенно важно для групп с общими scope-переменными: имя переменной берётся из конструктора профиля, а не из агрегированного источника/списка.
- Проверено: 325 frontend-тестов и production build; Chromium подтвердил метки `NFQWS_ARGS_CUSTOM` и `NFQWS_ARGS_UDP` в заголовках соответствующих профилей.

## Пункт 9. Удаление подсказок из раздела списков
