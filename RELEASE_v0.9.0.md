# v0.9.0 — Совместимость проверки конфигураций с Zemidala

- В подготовке чужого `.conf` добавляются отсутствующие стандартные `NFQWS_BASE_ARGS`, `MODE_LIST`, `MODE_ALL`, `MODE_AUTO` и `NFQWS_EXTRA_ARGS`. Пути формируются для фактической раскладки роутера: `/opt` на Keenetic/Entware и `/` на OpenWrt. Явно заданные значения, включая пустые, сохраняются.
- Исправлена ошибка `Need queue number (--qnum)` при проверке. Dry-run получает `--qnum` и `--user` из конфигурации, а при отсутствии использует `300` и `nobody`; `--fastpath-workaround=auto` добавляется по умолчанию, как в `dryRun()` Zemidala.
- Границы `NFQWS_ARGS_CUSTOM` теперь совпадают с `splitNew()` Zemidala: сохраняются пустой профиль до первого `--new`, соседние и завершающие разделители; `--new=` начинает пустой профиль, `--new=имя` добавляет `--name=имя`.
- Проверка по-прежнему не исполняет команды из чужого файла, а доступные файлы Lua/blob/list разрешает только в каталогах текущей установки. Проверочный автосписок остаётся отдельным временным файлом.

## Проверки

- Rust: полный набор unit и integration tests, `cargo fmt`, Clippy с `-D warnings`.
- Web: 201 тест, проверка TypeScript и production-сборка.
- Релизный workflow проверяет shell-скрипты, зависимости и ARM64-сборку. Bash/sh недоступны в локальном Windows окружении, поэтому shell preflight локально не выполнялся.
- Физического роутера в этой среде нет; тестирование на роутере не заявляется.
