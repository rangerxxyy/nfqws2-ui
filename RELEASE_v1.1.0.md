# v1.1.0 — рабочий журнал

Начало работы над ТЗ: 2026-10-25 19:04 UTC. Релизный тег не создавать раньше 2026-10-25 20:34 UTC и только после выполнения требований и проверки доступных сред.

## План коммитов

1. Удалить страницы «Сообщество» и «ASN»: навигацию, TS API/types/handlers/styles, Rust endpoint/module и переключатели подбора, которые существуют только для каталога сообщества. ASN-данные, используемые диагностикой сайта/маршрута, оставить: это не страница «ASN».
2. «Профили»: перенести понятия и действия из `currentProfiles`/`viewSettings` Zemidala на имеющийся разбор профилей конфигурации Rust; определить по текущему коду, какие CRUD/активация безопасно поддерживаются nfqws2, не имитировать профильную сущность поверх несовместимых аргументов.
3. «Резервные копии»: проверить и открыть пользователю имеющийся Rust snapshot API и панель списка; добавить отсутствующие безопасные действия (в частности, удаление с подтверждением), если их допускает модель снимков.
4. «Журнал изменений»: перенести идею Zemidala `historyScan`/`historyOf` на backend Rust и существующие атомарные снимки, предоставить список с датой, причиной и изменёнными файлами.
5. «Журнал»: подключить отдельную страницу к существующему `/api/logs`, с источниками UI/nfqws2, ограниченным tail, поиском/фильтром, автообновлением, скачиванием и только безопасной очисткой.
6. Версия, changelog, `RELEASE_v1.1.0.md`, регрессия, сборка для ПК и ARM64 CI; релиз после минимального рабочего интервала 90 минут.

## Первичное изучение

- Backend: Rust, Axum и Tokio. Frontend: TypeScript/TSX, React 19 и Vite.
- В Zemidala изучены `currentProfiles`/`viewSettings`, снимки и история (`snapshotCreate`, `historyScan`, `historyOf`), а также меню журналов. Его реализация PHP/JS; переносим модели поведения на Rust API и TSX, без копирования серверной реализации.
- В нашем коде уже есть профильный редактор внутри конфигурации и парсер конфигурации nfqws2; отдельного маршрута «Профили» нет.
- Уже есть Rust snapshots API (список/создание/восстановление/экспорт/импорт/удалённое хранение); интерфейс подготовлен в `panel.ts`, но страница скрыта как недоступный маршрут. Сверить фактическое наличие удаления снимка и связать UI после изучения схемы.
- Rust `GET /api/logs` уже существует; отдельная TS-страница и API-клиент отсутствуют.
- Страница сообщества объединяет provider-стратегии и генератор ASN-префиксов. Удаление UI/API этих функций не должно стирать ASN-сведения, необходимые диагнозу и отчёту.
- Пункт 6 в предоставленном ТЗ обрывается: не добавлять для него функцию; записать запрос уточнения в журнал релиза.
