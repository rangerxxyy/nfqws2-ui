# v0.8.3 — Проверка конфигурации и постепенные результаты автоподбора

- В «Авто-подборе стратегии» результаты отображаются по мере завершения кандидатов. Подтверждённый результат после принудительной остановки остаётся доступен для предпросмотра и применения.
- Добавлен компактный раздел «Проверка конфигурации» в «Диагностика и автоматика». Конфиги можно добавить текстом, по HTTPS-ссылке или из файла `.conf`, затем сравнить с текущим конфигом на одинаковом наборе сайтов.
- По результатам аудита Zemidala известные пути Lua/blob приводятся к файлам текущей установки; каждая стратегия проверяется до трёх раз подряд, повторы прекращаются после первой неудачи. Сравнение показывает счётчик успешных попыток.
- Ограничения проверки: до трёх конфигов, до трёх сайтов, файл до 64 КиБ; ссылка должна быть HTTPS на публичный домен. Поддерживаются статические аргументы; shell не исполняется. Активный конфиг и сервис не меняются.
- URL с точкой в конце hostname теперь отклоняются, чтобы DNS pin и hostname запроса оставались одним адресом.
- В полном пакетном подборе результат каждой проверенной стратегии (включая неудачные/неопределённые) появляется сразу; список ограничен 256 строками, подтверждённые варианты сохраняются в приоритете.
- Настройки собственной стратегии в режиме «Своя стратегия» сворачиваются и раскрываются; текстовые размеры унифицированы.

## Проверки

- Web: 201 тест пройден; TypeScript, production-сборка и `pnpm audit --prod` прошли.
- Rust: 275 тестов, форматирование, Clippy и `cargo audit` прошли.
- Linux release workflow также успешно выполнил ShellCheck, preflight shell-тесты и ARM64 cross-build.
- Роутерная проверка не выполнялась: в этой сессии нет подключённого тестового роутера. Локальная страница открывается, но API возвращает HTTP 500 из текущего окружения, поэтому ручную проверку с работающим backend не подтверждаю.
