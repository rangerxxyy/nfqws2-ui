# Changelog

## [0.2.5] — Диагноз напрямую / сейчас и QUIC без HTTP3 curl

- В диагнозе добавлено настоящее сравнение HTTPS напрямую (мимо nfqws2) и через обычный маршрут роутера. Результаты и времена вынесены в две карточки; технические этапы сворачиваются в подробности.
- Добавлена проверка QUIC Initial через встроенную Lua-криптографию установленного nfqws2 с `--intercept=0`. Отдельные соединения сравнивают текущий доступ и прямой UDP bypass; ответы сверяются с идентификатором проверочного соединения. HTTP3 curl используется при наличии, Alt-Svc показан отдельно; ответ QUIC не выдаётся за полный HTTP/3-запрос.
- Трассировка показывает явные плашки «Открылся / Не открылся напрямую» и «через текущую стратегию nfqws2», отдельно обрабатывает HTTP-ошибки и недоступные этапы.
- Bypass ограничен одним адресом/портом и соединениями самого роутера. Диагностика продолжает очистку при закрытии вкладки; stderr команд firewall сохраняется для реальных ошибок. Устранён deadlock большого вывода `iptables`, который обрезался на 8 КБ и мог блокировать pipe; policy mark дополнительно читается из целевой цепочки.
- Сохранена MIT-атрибуция генератора QUIC в исходниках и релизном архиве; в интерфейсе сторонние названия не отображаются.
- Проверено: 105 Rust-тестов, 78 frontend-тестов, локальный UDP loopback, Clippy, production build и аудит зависимостей; в браузере проверен ответ реального Windows backend. Реальный Keenetic smoke-test не выполнен.

## [0.2.4] — Запуск трассировки без полного дампа firewall

- Чтение `iptables -S` больше не блокирует трассировку: запрос без nfqws2 запускается через изолированные точечные правила, а ограничения firewall показываются из реальной ошибки `iptables`.
- Для тестового nfqws2 занятые очереди сверяются по доступному снимку правил, активным аргументам процесса и `/proc/net/netfilter/nfnetlink_queue`; если файл ядра недоступен, тестовая очередь не запускается.
- Исправлена ошибочная инструкция smoke-test, требовавшая предварительное чтение встроенных hooks.
- Проверено локально: Rust/frontend тесты, Clippy, форматирование, сборка UI и аудит зависимостей. Нужен повторный smoke-test на роутере.

## [0.2.3] — Исправление запуска трассировки на Keenetic

- Убрана блокирующая проверка на наличие строк политики `-P PREROUTING/OUTPUT/POSTROUTING`: BusyBox/сборки iptables могут не выводить их, хотя таблица доступна.
- Теперь создание точечных временных цепочек и подключение к нужным hooks определяет доступность firewall. При ошибке интерфейс показывает команду и ответ `iptables`; общие правила не очищаются.
- Проверено локально: Rust/frontend тесты, Clippy, форматирование, production build и аудит зависимостей. Проверка живого трафика на целевом роутере требует его SSH-доступа.

## [0.2.2] — Трассировка и удаление неподключённых разделов

- Устранён отказ «firewall не менялся» на роутерах, где init-скрипт настраивает INPUT/OUTPUT: теперь трассировка проверяет только наличие mangle hooks PREROUTING, OUTPUT и POSTROUTING, которые ей нужны.
- Backend больше не читает init-скрипт ради этой проверки. Временные правила по-прежнему добавляются в уникальные цепочки и удаляются точными командами; общие цепочки и правила firewall не очищаются.
- Удалены разделы «Журнал и Счётчики» и «Снимки и Копии» вместе с фиктивными счётчиками, формой NAS и UI-обработчиками. Журнал `--debug` в трассировке сохранён.
- Проверено: Rust-тесты для доступных и отсутствующих hooks, frontend-тесты на отсутствие удалённых экранов и навигации, Clippy, сборка UI и аудит зависимостей.

## [0.2.0] — Исправление маршрута трассировки и прокрутки

- Исправлен корень ложных одинаковых таймаутов: проверочные пакеты теперь перехватываются отдельными цепочками в `POSTROUTING`/`PREROUTING` и после тестовой очереди не попадают в основную очередь nfqws2. Базовый запрос проходит через те же hooks без тестового nfqws2.
- При режиме Keenetic «только устройства политики» backend распознаёт текущую policy mark nfqws2 и ставит её проверочным TCP-соединениям до выбора маршрута, как в остальном трафике роутера.
- Таймауты теперь указывают достигнутый этап TCP, TLS или HTTP; отсутствие ответов в обоих режимах больше не подписывается как внутренняя техническая ошибка.
- Исправлен viewport flex-контейнер: основная область и длинный журнал трассировки снова прокручиваются. Убрано упоминание стороннего проекта из текста панели.
- Проверено локально: регрессионные тесты hooks/policy mark/сводки/прокрутки, Rust-тесты, frontend-тесты, Clippy и сборка UI. Linux ARM64 пакет собирается CI; smoke-test на целевом Keenetic остаётся необходим для подтверждения реального сетевого маршрута и описан отдельно.

## [0.1.17] — Трассировка домена через изолированный nfqws2

- Добавлен отдельный раздел трассировки HTTP/HTTPS: сравнивает ответ роутера без тестового nfqws2 и с временным процессом `nfqws2 --debug`, затем показывает обнаруженные hostname, профиль, действия Lua, предупреждения и ограниченный журнал.

- Операция выполняется в фоне, имеет статус и отмену; сериализована с другой диагностикой. QUIC/HTTP3 остаётся отдельной проверкой в разделе «Проверка сайта».
- Проверено локально: 93 Rust-теста, 57 frontend-тестов, Rust fmt/Clippy, production build и `git diff --check`. Linux ARM64 CI и сборка релизного пакета запускаются перед публикацией. Проверка на целевом роутере не выполнена; см. `docs/site-trace-smoke-test.md`.

## [0.1.12] — Снимок реальных профилей nfqws2

- Добавлен `GET /api/nfqws2/runtime`: Rust находит однозначный работающий процесс по установленному бинарнику и PID, читает его `/proc/<pid>/cmdline`, делит аргументы на группы `--new` и возвращает только сводку фильтров, Lua-стратегий и payload.
- В блоке конфигурации фактически запущенные группы показаны отдельно от статически разобранных секций файла; снимок обновляется после запуска, остановки, перезапуска и применения конфига.
- Сырые argv и значения Lua-параметров не отдаются браузеру. Ответ прямо указывает, что обнаруженные аргументы не подтверждают прохождение трафика или эффективность стратегии.
- Шапка центрирует название панели на широком экране и переносит его с блоком версий на отдельную строку на обычной ширине. RAM/CPU и управление службой занимают меньше места; перезапуск показывает вращение иконки.
- Диагностика явно показывает HTTP-код, различает ошибки HTTP/3 и QUIC и запускает запрос только если curl поддерживает `--http3-only` и собран с HTTP/3.
- Проверено: полный набор Rust-тестов и Clippy; 46 frontend-тестов, TypeScript typecheck и production build.
- На реальном Keenetic этот endpoint в рамках выпуска не проверен.
- Локальный smoke-тест диагностики получил HTTP 206 по HTTP и HTTPS; QUIC отмечен «не проверен», поскольку curl в Windows не поддерживает `--http3-only`. Проверка маршрута и списков недоступна без Linux-утилиты `ip` и установленной конфигурации роутера.

## [0.1.11] — Проверка сайта и компактная шапка

- Подключена проверка сайта через Rust API: DNS роутера и Cloudflare DoH, TCP 443, HTTPS/TLS, HTTP 80, контрольное SNI, маршрут ядра, совпадения в доменных/IP-списках. HTTP/3 проверяется при поддержке установленным curl; отсутствие возможности показывается явно.
- Проверки ограничены временем и размером результата, выполняются по одной; введённое имя нормализуется, назначения закреплены за проверенными публичными IP. Произвольные команды, порты, локальные адреса, редиректы и параметры curl из HTTP не принимаются.
- Пока не реализованы изолированное сравнение «с nfqws2 / без nfqws2», доказательство поломки стратегией и точное сопоставление профилей. Несовпадение DNS и сетевые таймауты не объявляются доказательством DPI-блокировки. Это начальный рабочий диагностический поток, а не полная функциональная копия zemidala.
- Статус, компактные кнопки перезапуска/остановки и RAM/CPU размещены в одной строке; на узком экране строка прокручивается. Заголовок редактора — «Конфигурация»; фактический путь доступен в подсказке.
- Убраны секции-переходы, бейдж «Проверка не выполнялась», кнопка сравнения, поле/кнопка «Добавить в черновик» и описания над списками. Редактор списка, поиск, импорт, экспорт и сохранение сохранены.
- Живой HTTP-запрос диагностики и отображение ответа проверены на Windows; это не аппаратная проверка Keenetic. Эталон порядка диагностических проб: [zemidala/nfqws2-ui](https://github.com/zemidala/nfqws2-ui/blob/631878b8b9a6908d106904c188a83afb7aa43dbf/src/www/api.php).

## [0.1.10] — Сохранение структуры конфигурации при быстрых правках

- Быстрые настройки изменяют черновик через Rust API `/api/nfqws2/config/preview`; удалена замена целой строки в TypeScript, которая могла повреждать многострочные значения и удалять комментарии.
- Парсер сохраняет все байты вне изменяемого значения, неизвестные переменные, комментарии, отступы и переводы строк. Дубликаты, незавершённые кавычки и неподдерживаемые исполняемые shell-фрагменты требуют raw-редактирования; backend их не выполняет.
- Выбор режима допускает только существующие непустые MODE_LIST/MODE_AUTO/MODE_ALL. Предварительное редактирование не записывает файлы и не перезапускает службу; запись по-прежнему выполняется отдельной кнопкой применения с ревизией, backup и повторным чтением.
- Добавлены проверки на конфигурации upstream-пакета и отрицательные сценарии API. Полный CRUD профилей и проверка стратегий установленным бинарником ещё не реализованы.

## [0.1.9] — Существующие списки, Keenetic RAM и шапка

- Tokio обновлён до 1.54.1 для устранения RUSTSEC-2026-0384, обнаруженного аудитом зависимостей перед выпуском.

- Существующие стандартные списки обнаруживаются в каталоге `lists`, даже когда конфиг или выбранный режим не содержит ссылки на них. В частности, `user.list` доступен при MODE_ALL. Явные пути имеют приоритет; проверки каталога, symlink, ревизии, резервной копии и повторного чтения сохранены.
- RAM/CPU получают данные Keenetic RCI тем же способом, что XKeen UI (`memtotal`, `memory`, `cpuload`). При недоступности RCI используется `/proc`; источник указан в подсказке. Подстановка или округление объёма до 512 МБ не применяется.
- Кнопки перезапуска и остановки перенесены в левую группу к статусу. Обновление nfqws2 расположено слева в группе версий, обновление UI — справа; добавлена явная подпись UI.
- Добавлены проверки открытия и сохранения `user.list` без ссылки в конфиге, наличия всех пяти списков, разбора RCI и расположения/привязок кнопок. На реальном роутере этот выпуск ещё не проверен.

Источники поведения: [zemidala, inventory каталога lists](https://github.com/zemidala/nfqws2-ui/blob/2096708c2aa6a26028ca3bfc36e2c87c090a7134/src/www/api.php), [XKeen UI, системные метрики RCI](https://github.com/zxc-rv/XKeen-UI/blob/4ac36362bebb90ca28d66872cf72e79e2de91747/backend/src/system.rs).

## [0.1.5] — Исправление запуска интерфейса и проверка Lua/blob файлов

- Исправлен production bundle: React теперь собирается с `NODE_ENV=production`, поэтому браузер не падает на отсутствующем Node `process` и монтирует интерфейс.
- Добавлена CI-проверка, запрещающая выпуск JS bundle с неразрешённым `process.env.NODE_ENV`.
- Backend читает literal-ссылки Lua/blob из активного `nfqws2.conf` без выполнения shell, отмечает динамические и относительные пути отдельно и проверяет абсолютные файлы на существование и чтение (включая gzip-вариант Lua).
- В TSX удалены придуманные пути Lua/blob; вместо них отображаются только ссылки из ответа Rust backend с фактическим состоянием файла.
- Целевой роутер и его конкретная конфигурация в этой проверке недоступны; это остаётся проверить после установки.

## [0.1.4] — TSX-интерфейс и базовое управление nfqws2

- Удалён `web/index.html`: Vite собирает UI в стабильные JS/CSS-ассеты, а Rust отдаёт только минимальную загрузочную оболочку на `/`; интерфейс и загрузка стилей настраиваются из TypeScript/TSX.
- Начальные метрики, статус, очередь, мониторинг, провайдер, ASN, Telegram/NAS-параметры и результаты заменены реальными данными API или нейтральными состояниями ожидания; отсутствующие ответы больше не изображаются как успешные.
- Перенесены разметка, компоновка и встроенные стили из приложенного `nfqws2_ui_web_management_panel.html` в React/TSX-компонент `web/src/App.tsx`; Rust backend и TypeScript API-клиент остаются отдельными слоями.
- Внешние CDN-скрипты и inline JavaScript из HTML не загружаются: обработчики переведены в делегирование событий TypeScript, а существующие API-операции подключены к конфигурации, спискам, службе и журналам.
- Удалены встроенные демонстрационные значения и фиктивные действия; отсутствующая интеграция остаётся явно отключённой. По запросу пользователя полностью удалены вход, пароль, сессия и CSRF из панели и Rust API.
- Установщик больше не запрашивает пароль, удаляет устаревший файл пароля и после health-check печатает кликабельные ссылки с обнаруженными IPv4-адресами роутера и выбранным портом.
- Добавлены allowlist API для чтения и записи существующих списков с проверкой ревизии, валидацией, резервной копией, атомарной записью и повторным чтением.
- По активным literal-параметрам nfqws2 определяется фактический путь списка; неоднозначные ссылки не угадываются. Дедупликация сохраняет комментарии, порядок и первое вхождение, изменяя только локальный черновик до явного сохранения.
- Добавлен диагностический `GET /api/nfqws2/installation`; кнопка применения конфига доступна только после подтверждения backend, что файл доступен для записи.
- Проверены операции интерфейса и базового backend: служба, `nfqws2.conf`, обнаруженные списки и диагностика путей. Установка и управление на целевом роутере в этом релизе не проверены.
- Расширенные функции мониторинга, автоподбора, community/ASN, Telegram, NAS и обновлений пока отключены, поскольку их backend-интеграции не реализованы.

## [0.1.0] — first public build

- Added authenticated sessions with Argon2 password hashes, CSRF protection, rate limiting, security headers, and conservative service status.
- Added nfqws2 start/stop/restart via the detected init script; status requires init confirmation and a matching PID/cmdline.
- Added a save-and-apply configuration action that uses only a confirmed service state and the supported init start/restart command.
