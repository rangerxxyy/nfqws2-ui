# Changelog

## [1.2.1] — Исправление проверки панели и профилей

- Команды установки, обновления и проверки состояния панели предпочитают Entware `wget`, если он доступен. Это предотвращает сбой BusyBox `wget` на роутерах, где он затеняет рабочий `/opt/bin/wget` в `PATH`.
- Справочник конструктора профилей стал адаптивным и показывает русские пояснения к параметрам.
- Исправлена проверка параметров Lua `fake:repeats` и `fakeddisorder:pos`, чтобы существующие аргументы не отображались как неизвестные.

## [1.2.0] — Расширенный конструктор профилей

- Добавлен подробный конструктор runtime-профилей nfqws2 с условиями фильтрации, списками доменов и IP, payload и упорядоченными Lua-шагами.
- Параметры nfqws2 и типы трафика загружаются из установленной версии; Lua-функции и их параметры — из установленных скриптов.
- Lua-параметры с необязательным значением, например `tcp_md5[=hex]`, доступны в конструкторе и распознаются предупреждениями.
- При медленной или неполной справке `nfqws2 --help` каталог перечитывается с увеличенным тайм-аутом; состояние полноты видно в разделе профилей.
- Профили можно создавать, копировать, переименовывать, менять порядок аргументов и вставлять из текста чата.
- Добавлены справка по Lua-параметрам и предупреждения о неизвестных аргументах и перекрытии правил.
- Перед применением профилей выполняются проверка конфигурации, резервное копирование и безопасный перезапуск с откатом при ошибке.
- Журнал nfqws2-UI и nfqws2 позволяет очистить выбранный источник после подтверждения.
- Внутренний helper резервного копирования панели получил отдельное имя, чтобы не конфликтовать с другими UI.

## [Unreleased]

- Удалена дублирующая сводка аргументов в начале редактора профиля: после заголовка и предупреждений сразу отображаются поля и конструктор.
- В окне выбора параметров профиля добавлена навигация стрелками, переход к началу и концу списка, а также связи групп для экранных дикторов.

## [1.1.0] — Профили, резервные копии и журналы

- Разделы «Сообщество» и «ASN» временно удалены, будут возвращены позже.
- Добавлен раздел runtime-профилей nfqws2: штатные группы аргументов доступны для просмотра, пользовательские из `NFQWS_ARGS_CUSTOM` можно добавлять, редактировать, удалять и менять местами; применение проходит проверку, резервное копирование и перезапуск с откатом при ошибке.
- Страница резервных копий подключена к Rust API; доступны создание, скачивание, восстановление, импорт архива и удаление локальной копии с защитой закреплённых снимков.
- Добавлен журнал изменений по различиям хэшей файлов между снимками; новые снимки сохраняют версию UI, старые записи остаются совместимыми.
- Добавлен журнал nfqws2-UI и nfqws2 с фильтром, обновлением при открытой странице и скачиванием.

## [1.0.7] — Компактная диагностика и редактор списков

- Очередь диагноза стала компактнее: этапы показаны без нумерации, результаты проявляются по порядку, подписи QUIC сокращены до статуса, HTTP-кода и времени ответа.
- Редактор `.list` стал компактнее: удалена отдельная строка поиска, переключатель вида перенесён к действиям списка, добавлены подтверждаемая очистка черновика и полноэкранный режим.
- В текстовом редакторе списков уменьшены межстрочный интервал и размер шрифта; список записей получил более читаемый шрифт и состояния наведения.
- Применение конфигурации сохраняет журнал восстановления до завершения проверки службы; при старте backend восстанавливает исходный файл после прерванного применения и не затирает внешние изменения.
- Подсказки действий редактора списка уточняют назначение сохранения, удаления, импорта, экспорта и очистки.
- В окне обновления появилась повторная загрузка списка версий, а длинные команды в разделе «О панели» больше не перекрывают кнопку копирования.
- Меню выбора сохраняет компактный вид и состояние клавиатурного фокуса при открытии у верхнего или нижнего края окна.

## [1.0.6] — Уточнение меню и адаптивности

- Очередь проверки сайта теперь подсвечивает этапы во время ожидания ответа роутера, не помечая их успешными до получения фактических результатов.
- Закрывающееся меню выбора сразу скрывается от скринридера и возвращает listbox-состояние при повторном открытии.
- Описания релизов сохраняют GitHub-таблицы, включая выравнивание столбцов, ссылки и выделение текста.
- Общее меню выбора раскрывается вверх, когда снизу экрана недостаточно места.
- Подсказка кнопки закрывается сразу после её нажатия или удаления при смене страницы.
- Меню выбора получило более компактные строки и палитру: нейтральный выбранный пункт с белой галочкой, синяя подсветка наведения и фокуса.
- При открытии мышью выбранный пункт остаётся нейтральным; синяя подсветка появляется при наведении или клавиатурной навигации.
- Длинные списки выбора используют доступную высоту окна до 34rem, чтобы списки часовых поясов не обрезались до нескольких строк.

## [0.9.8] — Поиск сети по домену или IP

- Генератор ASN принимает номер автономной системы, публичный IPv4 или домен.
- Для домена или IP определяется сеть через RIPEstat; найденные IPv4-префиксы добавляются в `ipset.list`.
- Добавлены быстрые значения популярных ASN; кнопки только заполняют поле и не запускают запись списка.

## [0.9.7] — Компактный подбор и сети ASN

- Форма «Авто-подбора стратегии» стала компактнее: домен и транспорт сгруппированы, подписи и элементы управления занимают меньше места.
- Генератор ASN загружает IPv4-префиксы RIPEstat, объединяет их с `ipset.list` и удаляет уже присутствующие или вложенные диапазоны.
- Перед записью проверяются права доступа и актуальная версия `ipset.list`; пустой или чрезмерно большой ответ не изменяет список.

## [0.9.6] — Получение обновлений и проверка стратегий

- Список версий панели загружается короче, поэтому проверке обновлений не приходится скачивать весь архив из 80 релизов.
- Для ответа GitHub увеличено время ожидания; превышение лимита ответа и таймаут теперь показываются как разные ошибки.
- В режиме проверки собственных стратегий результаты каталога и диагностики заморозки не учитываются как источник стратегий.
- Результаты проверки доменов выровнены, а время ответа выделено бирюзовым цветом.

## [0.9.5] — Удобства редактора конфигурации

- Установщик повторно загружает архив и SHA-256 с уникальным cache-buster, если GitHub CDN временно отдаёт несовпадающие версии файлов.
- Исправлено получение списка версий панели: проверка панели и nfqws2 использует одинаковый выбор wget, включая `/opt/bin/wget`.
- Если запуск системного `curl` не удался, мониторинг сохраняет исходную причину backend вместо ложного сообщения о сетевом сбое.
- TCP, TLS, HTTP и передача в этом случае получают статус «недоступно»; общая причина, например отсутствие утилиты, показывается пользователю.
- Редактор конфигурации можно очистить с подтверждением или развернуть почти на весь экран.
- Очистка удаляет только текст черновика; применение изменений выполняется отдельно.
- Разделы «Отчёт для помощи» и «Резервные копии» временно скрыты из интерфейса.
- Для проверки сторонней конфигурации принимаются `.txt` и `.conf`.

## [0.9.4] — Импорт сторонней конфигурации из TXT

## [0.9.1] — Лимиты сравнения чужих конфигураций

- Число конфигов для одного сравнения увеличено с 3 до 10, а целей — с 3 до 15, как в текущей реализации Zemidala.
- Лимиты проверяются на backend; повторы и проверка каждой конфигурации продолжают выполняться последовательно, доступна ручная остановка.
- Интерфейс показывает новые лимиты и предупреждает, что большие наборы могут занять время.

## [0.9.0] — Совместимость проверки конфигураций с Zemidala

- Проверка `.conf` дополняет отсутствующие `NFQWS_BASE_ARGS`, `MODE_LIST`, `MODE_ALL`, `MODE_AUTO` и `NFQWS_EXTRA_ARGS` стандартными значениями Zemidala, учитывая раскладку `/opt` на Keenetic и `/` на OpenWrt.
- `nfqws2 --dry-run` запускается с `--qnum` и `--user` из конфига (или значениями по умолчанию `300` и `nobody`) и добавляет `--fastpath-workaround=auto`, если параметр не задан.
- Разделители custom-профилей `--new` сохраняют пустые профили в начале, между соседними разделителями и в конце; пустой `--new=` обрабатывается как у Zemidala.
- Сборка профилей остаётся статической и безопасной: конфиг не выполняется как shell, пути файлов проверяются относительно текущей установки, автосписки изолированы.

## [0.8.13] — Выбор повторов при проверке чужого конфига

- Для проверки конфигурации можно выбрать от 1 до 5 последовательных сетевых запросов; по умолчанию остаётся 3.
- Совпадение считается подтверждённым только при успехе выбранного числа повторов; после первого неуспешного запроса серия прекращается.

## [0.8.12] — Совместимость с повторными присваиваниями в чужом конфиге

- Проверка `.conf` поддерживает последовательные литеральные присваивания аргументных переменных и шаблон Zemidala `VAR="$VAR …"` для добавления профилей.
- Разделители `--new` из `NFQWS_ARGS_CUSTOM` сохраняются при сборке профилей; итог соответствует порядку статических присваиваний shell.
- Другие shell-переменные, подстановки команд и неподдерживаемая экранизация по-прежнему отклоняются без исполнения shell-кода.

## [0.8.11] — Поддержка вложенных режимов в чужом конфиге

- Проверка стороннего `.conf` статически раскрывает стандартную цепочку `NFQWS_EXTRA_ARGS="$MODE_AUTO"` → `MODE_LIST` / `MODE_ALL`.
- Параметры `--hostlist`, `--hostlist-exclude` и `--hostlist-auto` проходят ту же безопасную адаптацию путей, что и параметры, заданные литералами.
- Поддерживаются `${MODE_*}` и одинарно-кавыченные литералы внутри режима. Циклы, неизвестные shell-переменные и чрезмерно вложенные ссылки отклоняются; shell-код не исполняется.

## [0.8.10] — Lua-модули из установленной конфигурации

- `--lua-init=@путь` в стороннем `.conf` сопоставляется с обычным файлом в каталоге Lua текущей установки, включая `.lua.gz`; совпадение только по имени с уже запущенным модулем больше не используется.
- Неизвестные пути, отсутствующие Lua-файлы, traversal и символические ссылки отклоняются до dry-run.
- При наличии `--lua-desync` в конфиг добавляются доступные `zapret-lib.lua`, `zapret-antidpi.lua` и `zapret-auto.lua`, как при адаптации Zemidala.

## [0.8.9] — Безопасная адаптация путей blob-файлов

- Файловые `--blob=имя:@путь` из известных раскладок nfqws2/zapret сопоставляются только с обычными файлами в каталоге blobs текущей установки.
- Неизвестные абсолютные пути, отсутствующие файлы, traversal и символические ссылки отклоняются до dry-run; inline `0x...` не подменяется одноимённым активным blob, числовое смещение сохраняется.

## [0.8.8] — Полная сборка профилей стороннего `.conf`

- Подготовка проверочного процесса повторяет порядок профилей Zemidala: custom через `--new`, затем UDP, QUIC+IPSET, QUIC+дополнительные аргументы, TCP+IPSET и TCP+дополнительные аргументы.
- `--new=имя` в пользовательских профилях преобразуется в поддерживаемый `--name=имя`; управляющие параметры запуска удаляются из глобальных аргументов.
- `nfqws2 --dry-run` проверяет собранные группы профилей; сетевое сравнение явно обозначено как HTTPS/TCP и не выдаётся за тест UDP/QUIC.

## [0.8.7] — Адаптация путей сторонних конфигураций

- Проверка `.conf` сопоставляет пути из раскладок nfqws/nfqws2 и zapret с файлами текущей папки списков, если файл существует.
- Разрешаются только обычные файлы внутри установленного каталога списков; неизвестные пути, отсутствующие файлы, переходы за каталог и символические ссылки отклоняются до запуска тестового процесса.
- `--hostlist-auto` копируется именно из пути проверяемого конфига после безопасного сопоставления; если файла нет в активном каталоге списков, используется пустая временная копия. `--hostlist-auto-debug` отключается.

## [0.8.6] — Изоляция автосписков при проверке `.conf`

- Сверка чужих конфигураций больше не передаёт исходный путь `--hostlist-auto` проверочному процессу. Для каждого сравниваемого конфига создаётся отдельная временная копия активного автосписка.
- Временный каталог создаётся эксклюзивно с приватными правами и удаляется после успеха, ошибки или отмены проверки. Копирование ограничено 4 МиБ.
- `--hostlist-auto-debug` исключён из пробы, чтобы сторонний конфиг не мог записать диагностический файл по произвольному пути; раздельный формат аргумента отклоняется.
- Описание проверки уточняет обработку автосписка и отключение отладочной записи.

## [0.8.5] — Защита памяти при проверке чужого конфига

## [0.3.2] — Адаптивные повторы 16-КБ проверки

- В таблице 16-КБ диагностики результаты выделяются по смыслу: подтверждённый обрыв без решения — красным, успешная проверка или стратегия с тремя повторами на этом сайте — зелёным, совпадение по ASN — янтарным, неопределённый результат — нейтрально.
- Для подтверждённой стратегии на введённом пользователем домене доступен предпросмотр и применение прямо из раздела 16 КБ. Профиль ограничивается этим доменом; перед записью выполняется `nfqws2 --dry-run`, создаётся резервная копия, служба перезапускается с откатом при ошибке.
- Кандидаты, найденные только на эталонных IP/сетях, не применяются автоматически к подсети: их требуется проверить отдельно на собственном домене.
- Базовая диагностика теперь отправляет один прямой и один маршрутный запрос для обычного ответа. Второй замер запускается только при тайм-ауте в диапазоне 16–20 КБ, чтобы проверить повторяемость обрыва.
- Такой порядок следует базовому проходу источника алгоритма и убирает до 40 лишних HTTP-трансферов при проверке штатного каталога из 20 сетей.
- Одиночный тайм-аут до тела ответа теперь показывается именно как тайм-аут; он не считается обрывом передачи и не запускает поиск fake-SNI.
- Трассировка режима объёма использует то же правило и сохраняет повтор при подозрении на границу.
- Проверено: Rust tests, Clippy, форматирование, release build и ARM64 musl check; полная проверка пройдёт в CI перед выпуском. Поведение полного сканирования на роутере для этого изменения отдельно не замерялось.

## [0.1.12] — Снимок реальных профилей nfqws2

- Добавлен `GET /api/nfqws2/runtime`: Rust находит однозначный работающий процесс по установленному бинарнику и PID, читает его `/proc/<pid>/cmdline`, делит аргументы на группы `--new` и возвращает только сводку фильтров, Lua-стратегий и payload.
- В блоке конфигурации фактически запущенные группы показаны отдельно от статически разобранных секций файла; снимок обновляется после запуска, остановки, перезапуска и применения конфига.
- Сырые argv и значения Lua-параметров не отдаются браузеру. Ответ прямо указывает, что обнаруженные аргументы не подтверждают прохождение трафика или эффективность стратегии.
- Шапка центрирует название панели на широком экране и переносит его с блоком версий на отдельную строку на обычной ширине. RAM/CPU и управление службой занимают меньше места; перезапуск показывает вращение иконки.
- Диагностика явно показывает HTTP-код, различает ошибки HTTP/3 и QUIC и запускает запрос только если curl поддерживает `--http3-only` и собран с HTTP/3.
- Проверено: полный набор Rust-тестов и Clippy; 46 frontend-тестов, TypeScript typecheck и production build.
- На реальном Keenetic этот endpoint в рамках выпуска не проверен.
- Локальный smoke-тест диагностики получил HTTP 206 по HTTP и HTTPS; QUIC отмечен «не проверен», поскольку curl в Windows не поддерживает `--http3-only`. Проверка маршрута и списков недоступна без Linux-утилиты `ip` и установленной конфигурации роутера.

## [0.1.7] — Списки и системный статус

- Исправлено включение вкладок списков, когда backend возвращает реальные имена файлов; `auto.list`, `exclude.list` и IP-списки становятся доступны, если они обнаружены в активной конфигурации.
- RAM рассчитывается по `MemAvailable`, с резервной оценкой доступной памяти для старых ядер; CPU и память обновляются каждые 3 секунды и отображаются с порогами нагрузки.
- `ISP_INTERFACE` заполняется именами интерфейсов, реально обнаруженных в `/sys/class/net`; придуманные варианты удалены.
- При подтверждённом перезапуске nfqws2 или применении конфигурации индикатор в статус-баре показывает вращающийся спиннер до получения результата.
- Локальные проверки не заменяют проверку на Keenetic; применение и перезапуск на целевом устройстве не проверены.

## [0.1.5] — Исправление запуска интерфейса и проверка Lua/blob файлов

- Исправлен production bundle: React теперь собирается с `NODE_ENV=production`, поэтому браузер не падает на отсутствующем Node `process` и монтирует интерфейс.
- Добавлена CI-проверка, запрещающая выпуск JS bundle с неразрешённым `process.env.NODE_ENV`.
- Backend читает literal-ссылки Lua/blob из активного `nfqws2.conf` без выполнения shell, отмечает динамические и относительные пути отдельно и проверяет абсолютные файлы на существование и чтение (включая gzip-вариант Lua).
- В TSX удалены придуманные пути Lua/blob; вместо них отображаются только ссылки из ответа Rust backend с фактическим состоянием файла.
- Целевой роутер и его конкретная конфигурация в этой проверке недоступны; это остаётся проверить после установки.

## [0.1.4] — TSX-интерфейс и базовое управление nfqws2

- Удалён `web/index.html`: Vite собирает UI в стабильные JS/CSS-ассеты, а Rust отдаёт только минимальную загрузочную оболочку на `/`; интерфейс и загрузка стилей настраиваются из TypeScript/TSX.
- Начальные метрики, статус, очередь, мониторинг, провайдер, ASN, Telegram/NAS-параметры и результаты заменены реальными данными API или нейтральными состояниями ожидания; отсутствующие ответы больше не изображаются как успешные.
- Перенесены разметка, компоновка и встроенные стили из приложенного `nfqws2_ui_web_management_panel.html` в React/TSX-компонент `web/src/App.tsx`; Rust backend и TypeScript API-клиент остаются отдельными слоями.
- Внешние CDN-скрипты и inline JavaScript из HTML не загружаются: обработчики переведены в делегирование событий TypeScript, а существующие API-операции подключены к конфигурации, спискам, службе и журналам.
- Удалены встроенные демонстрационные значения и фиктивные действия; отсутствующая интеграция остаётся явно отключённой. По запросу пользователя полностью удалены вход, пароль, сессия и CSRF из панели и Rust API.
- Установщик больше не запрашивает пароль, удаляет устаревший файл пароля и после health-check печатает кликабельные ссылки с обнаруженными IPv4-адресами роутера и выбранным портом.
- Добавлены allowlist API для чтения и записи существующих списков с проверкой ревизии, валидацией, резервной копией, атомарной записью и повторным чтением.
- По активным literal-параметрам nfqws2 определяется фактический путь списка; неоднозначные ссылки не угадываются. Дедупликация сохраняет комментарии, порядок и первое вхождение, изменяя только локальный черновик до явного сохранения.
- Добавлен диагностический `GET /api/nfqws2/installation`; кнопка применения конфига доступна только после подтверждения backend, что файл доступен для записи.
- Проверены операции интерфейса и базового backend: служба, `nfqws2.conf`, обнаруженные списки и диагностика путей. Установка и управление на целевом роутере в этом релизе не проверены.
- Расширенные функции мониторинга, автоподбора, community/ASN, Telegram, NAS и обновлений пока отключены, поскольку их backend-интеграции не реализованы.

## [0.1.0] — first public build

- Rebuilt the panel from a clean repository with React/TypeScript UI and a Rust local API.
- Added authenticated sessions with Argon2 password hashes, CSRF protection, rate limiting, security headers, and conservative service status.
- Added nfqws2 start/stop/restart via the detected init script; status requires init confirmation and a matching PID/cmdline.
- Added a save-and-apply configuration action that uses only a confirmed service state and the supported init start/restart command.
