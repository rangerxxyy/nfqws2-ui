# v0.9.5 — Точная причина сбоя мониторинга

- Ошибка запуска внешней утилиты, используемой мониторингом, больше не подменяется ложным сетевым отказом.
- Исходное сообщение backend показывается в итоговом статусе; этапы TCP/TLS/HTTP и передачи помечаются недоступными, если проверку невозможно запустить.
- Изменение вдохновлено сверкой с Zemidala v1.22.3: там отдельно показывается сбой PHP-модуля cURL. Здесь сохранена причина ошибки собственного Rust backend.

## Проверки

- Rust: тест запуска мониторинга с отсутствующей утилитой, полный набор тестов, форматирование и Clippy.
- Frontend: Vitest, TypeScript typecheck и production build.
- Release workflow проверит shell/installer, аудит зависимостей и ARM64 пакет.
- Проверка на физическом роутере не проводилась.
