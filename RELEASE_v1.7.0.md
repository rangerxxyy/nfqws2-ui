# v1.7.0 — Подбор стратегий QUIC

## Изменения

- В автоподборе стратегий доступен транспорт `QUIC · UDP 443` для одного домена. QUIC требует имя домена для SNI; IP-адреса отклоняются. Многосайтовый подбор остаётся только для HTTP и HTTPS.
- Для проверки nfqws2 формирует QUIC Initial. Ответ принимается только при совпадении Connection ID. Перед перебором проверяется прямое соединение; если QUIC уже отвечает, поиск завершается без лишней сетевой нагрузки.
- QUIC-кандидаты тестируются последовательно во временной NFQUEUE с UDP-правилами и свежим Initial для каждого повтора. Перебор ограничен текущими подходящими стратегиями, небольшим стандартным набором, историей и явно введённой стратегией. Полный каталог, TLS-стратегии сообщества и дополнительное уточнение отключены.
- Поиск не меняет конфигурацию. Пользователь может просмотреть подтверждённый вариант и явно применить его. Preview добавляет доменно-ограниченный UDP-профиль в `NFQWS_ARGS_CUSTOM`; существующие TCP-настройки сохраняются.
- После перезапуска применяется обычная проверка транзакции, но для QUIC оценивается QUIC Initial выбранного домена. HTTP-проверки других сайтов не используются как условие успешного QUIC-профиля. При неудаче срабатывает штатный откат.
- В результатах показывается QUIC Initial, а не искусственный HTTP-код. Молчание endpoint описывается как отсутствие подтверждённого ответа, но не как доказательство DPI-блокировки.

## Ограничения

- Проверяется QUIC Initial с коррелированным ответом, а не полный TLS-handshake, HTTP/3-запрос или загрузка страницы.
- Сайт может молчать, потому что не поддерживает QUIC или не отвечает на Initial. Такой результат сам по себе не устанавливает причину.
- Для запуска требуются доступные Lua-функции активного nfqws2 и корректно определённые системные пути.
