# v1.12.1 — Автоматическое применение подобранной стратегии

Автоподбор мониторинга теперь может сам менять стратегию для домена после устойчивой недоступности.

## Что изменилось

- Порог автоматического запуска — 3 или 4 последовательные ошибки. Предыдущий успешный ответ домена больше не требуется.
- Ошибки других сайтов не блокируют подбор. DNS, маршрут и Podkop пропускаются, поскольку смена Lua-стратегии не исправляет эти причины.
- Убраны задержка повторной проверки на пять минут и порог из двух ошибок; сохранённая настройка «2» при загрузке нормализуется до 3.
- Если включено «Автоматически применять подтверждённый результат», подтверждённая стратегия заменяет Lua-шаги точного профиля домена. Если точного профиля нет, отдельный профиль для домена ставится перед остальными, чтобы его правило не перекрывалось.
- Перед применением выполняются статическая проверка и `nfqws2 --dry-run`. Затем панель перезапускает службу и проверяет целевой и ранее доступные сайты; при неудаче конфигурация автоматически откатывается.
- В журнале мониторинга теперь указано, обновлён существующий профиль или добавлен новый.

## Ограничения

- Подбор запускается только для доменов из включённого мониторинга и одного домена за раз.
- Запускается ограниченный HTTPS подбор; стратегия меняется только если кандидат прошёл повторные проверки.
- Смена стратегии выключена по умолчанию и выполняется только при включённых «Автоподборе» и «Автоматически применять подтверждённый результат».
- Для подтверждения результата нужны работающий NFQWS2, доступные файлы Lua/blob и успешные контрольные проверки. При неудаче или неоднозначной конфигурации изменения отменяются.
- Проверка на Netcraze Hopper NC-3811 с KeeneticOS не проводилась.

## Проверки

- Rust: 524 unit/integration tests, Clippy (`-D warnings`), `cargo build --release` и `cargo check` для `aarch64-unknown-linux-musl` прошли локально.
- Frontend: 481 тест и production-сборка TypeScript/Vite прошли.
- `cargo audit` прошёл без найденных уязвимостей.
- Полный ARM64 cross-build бинарного файла и проверка на роутере выполняются только в CI/на устройстве и здесь не подтверждены.
