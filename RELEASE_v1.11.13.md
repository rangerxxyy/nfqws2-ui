# v1.11.13 — Проверка подключения Lua-функций

В этот выпуск входит ограниченная первая версия DPI Lab: импорт и анализ classic PCAP, TCP-потоки с отображением источника байтов, поля TLS ClientHello/SNI, таймлайн пакетов и локальные воспроизводимые эксперименты. Срез не включает PCAPNG, QUIC, живой захват, выполнение Lua, эмуляцию провайдерского DPI или изменение активной конфигурации.

Подсветка `NFQWS_ARGS` и текстовой стратегии использует общую палитру кода в тёмной и светлой темах.

Предупреждения перед применением теперь проверяют, что Lua-файл с используемой функцией подключён через `--lua-init` в `NFQWS_BASE_ARGS`. Это помогает найти ситуацию, когда параметры функции известны по установленному каталогу, но nfqws2 не загрузит скрипт при запуске. Предупреждение показывает строку конфигурации и не блокирует применение.

Имена файлов сравниваются без привязки к абсолютному пути. Если в `NFQWS_BASE_ARGS` есть shell-переменные, проверка пропускает этот вывод, чтобы не объявлять скрипт отсутствующим при неразрешённой ссылке.

Сверено с Zemidala: функция должна принадлежать загруженному Lua-файлу, указанному в параметрах запуска. Полная DPI Lab остаётся следующими этапами. Проверки: полный frontend suite, TypeScript, production build, Rust suite, `cargo fmt --check`, Clippy и cargo audit.
